# 0057. Ключи API: область — список операций контракта, журнал каждого обращения

**Статус:** принято, 24.10.2026.

**Контекст.** ИН-1: все функции — через REST API, описанный OpenAPI, с интерактивной документацией.
ИН-2: ключи для внешних систем с ограниченными правами (чтение наличия и каталога, импорт),
журнал обращений, отзыв.

**Решение:**
- **ключ** `pk_<префикс>_<секрет>`; в базе — префикс и хеш секрета. Ключ показывается один раз;
- **область** (наличие, каталог, импорт) — список операций контракта, которые она открывает.
  Проверка — в той же прослойке, что и права сотрудников: операция не из области — 403, даже если
  у «роли ключа» формально есть право;
- **журнал**: каждое обращение по ключу — время, операция, адрес, разрешено ли. Отзыв действует сразу;
- **документация**: `/api/docs` (Swagger UI) читает контракт `/api/v1/openapi.json`, собранный из того
  же файла, по которому генерируется сервер, — расхождений документации с API нет.

**Последствия:**
- **плюс:** сайт сети или 1С получают ровно то, что им нужно, и это видно в журнале;
- **минус:** область — фиксированный набор; ключ с точечными правами на отдельную точку не выпустить.

**Отвергнуто:**
- **OAuth 2.0 client credentials:** отдельный сервер авторизации ради трёх областей избыточен.
