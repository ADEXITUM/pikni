# 0042. События реального времени: триггеры БД → LISTEN/NOTIFY → WebSocket

**Статус:** принято, 24.10.2026.

**Контекст.** Остатки, статусы документов, чеки и сканы должны обновляться у всех, у кого открыт экран, не позже чем через 2 с (УВ-1). Экземпляров сервера может быть несколько, брокера сообщений нет.

**Решение:**
- **события объявляют триггеры** на `documents`, `scans`, `stock_balances`, `egais_messages`, `pos_receipts` — функцией `pikni_event(тип, id, темы)` в канал `pikni_events`. Ни один путь изменения (сервис, обмен с ЕГАИС, касса) не забудет событие, а доставляется оно только после фиксации транзакции;
- **событие — подсказка «перезапроси»**: тип, идентификатор и темы (`doc:{id}`, `location:{id}`, `product:{id}`, `shift:{id}`). Данные клиент получает обычным запросом, где действуют права, — по WebSocket ничего лишнего не утекает;
- **сервер слушает канал одним соединением** (`internal/platform/realtime`), восстанавливает его при обрыве и рассылает событие подписчикам темы. Медленный клиент не задерживает остальных: лишнее событие отбрасывается;
- **WebSocket `GET /api/v1/ws`** вне контракта OpenAPI: вход по cookie сеанса, Origin сверяется с адресом сервера, темы — только вида `вид:UUID`, не больше 100;
- **клиент** (`@pikni/api/live`) держит одно соединение на вкладку, переподключается с паузой до 10 с и после переподключения перезапрашивает данные открытых экранов — события за время обрыва могли пропасть.

**Последствия:**
- **плюс:** при согласовании заявки отправителем статус у получателя меняется сам — видно на защите;
- **минус:** NOTIFY не хранится — событие, объявленное, пока сервер перезапускается, теряется; это допустимо, потому что клиент после переподключения перезапрашивает всё;
- **минус:** проведение большого документа объявляет событие на каждую строку остатков; при объёмах сети это незаметно.

**Отвергнуто:**
- **объявлять события из кода сервисов:** легко забыть в одном из путей (обмен, касса), и событие ушло бы до фиксации транзакции;
- **данные в самом событии:** пришлось бы повторять проверку прав и ограничивать размер (8000 байт у NOTIFY);
- **отдельный сервис и брокер (Kafka, NATS):** избыточно для 50 пользователей; модуль изолирован и при росте выносится без правки бизнес-модулей.
