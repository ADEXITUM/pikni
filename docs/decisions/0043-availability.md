# 0043. Наличие по сети: один запрос с необязательными фильтрами и характеристиками в JSON

**Статус:** принято, 24.10.2026.

**Контекст.** Продавцу нужно найти позицию по сети (НЛ-1) с фильтрами по городу, точке, категории, виду, бренду, стране, объёму, крепости, цене и характеристикам категории, увидеть таблицу «вариант × точка» и карту (НЛ-2), предложить замену (НЛ-6). Ссылкой на результаты можно поделиться.

**Решение:**
- **один статический SQL-запрос** (sqlc) с необязательными фильтрами: пустой фильтр (null) не ограничивает выборку. Сортировка — выражениями `case` по параметру, страницы — смещением: позиций тысячи, а сортировок четыре;
- **точки фильтра задают, где считать остаток**: «в точках» (scopeQty), «по сети» и «здесь» (текущая точка пользователя) считаются одним проходом по остаткам;
- **характеристики категории** приходят одним параметром JSON: значение — совпадение по `attributes @> …`, объект `{"min", "max"}` — диапазон числа. В фильтрах показываются характеристики с отметкой «фильтруемая» из справочника категорий (решение 0023), поэтому новая характеристика появляется в фильтре без правки кода;
- **все фильтры живут в адресе страницы**;
- **скан марки нового образца** ищет товар по учёту марок сети — отсканировал бутылку и увидел, где ещё она есть;
- **похожие товары** — один запрос по варианту: другой объём или тара позиции, та же линейка, аналоги (тот же вид и объём, цена ±15 %, совпадают характеристики «для аналогов», есть в текущей точке);
- **карта** — Leaflet и подложка OpenStreetMap; точки берут координаты из справочника точек.

**Последствия:**
- **плюс:** нет построителя SQL в коде — запрос проверяется sqlc и читается целиком;
- **минус:** смещение на больших страницах медленнее ключевой пагинации — при тысячах позиций незаметно;
- **минус:** подложка карты требует интернета; без него точки и подписи остаются, фон пустой.

**Отвергнуто:**
- **сборка SQL в коде:** гибче, но теряется проверка запроса при генерации;
- **поисковый движок (Elasticsearch, Meilisearch):** избыточно для объёма каталога сети; полнотекстовый поиск PostgreSQL уже есть (решение 0025).
