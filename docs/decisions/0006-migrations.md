# 0006. Миграции goose только вперёд

**Статус:** принято, 22.10.2026.

**Контекст.** Схема БД должна быть одинаковой у разработчика, в CI и на стенде и храниться в git.

**Решение:**
- миграции — пронумерованные SQL-файлы goose в `api/db/migrations`;
- директивой `//go:embed` они встроены в бинарник `pikni-migrate`;
- откатов (Down) нет:
  - ошибка исправляется новой миграцией;
  - локальная база пересоздаётся командой `task db:reset`;
  - миграции пишутся совместимыми с предыдущей версией приложения («расширить → перенести → сузить»), поэтому откат приложения не требует отката схемы.
- Тестовые данные — отдельный файл `api/db/seed/dev.sql`, не миграция.

**Последствия:**
- **плюс:** на сервер не нужно копировать папку с миграциями;
- **плюс:** повторный запуск ничего не делает, goose помнит применённые версии;
- **минус:** ошибочную миграцию нельзя «откатить» — только исправить вперёд.

**Отвергнуто:**
- **Up и Down для каждой миграции:** код, который никто не запускает;
- **демо-данные в миграциях:** попали бы на рабочий сервер.
