# 0028. Публичная страница наличия — вне рамок ВКР

**Статус:** принято, 24.10.2026. Меняет состав приложений из решения 0009: `apps/public` не создаётся.

**Контекст.** ТЗ включало третье клиентское приложение — справочную страницу наличия для покупателей (бывшее НЛ-5): вход без пароля, подтверждение 18+, «есть / мало / нет» по магазинам, без цен и количеств. Тема ВКР — система учёта ТМЦ со сканером и отчётами. Страница не участвует ни в учёте, ни в сканировании, ни в отчётах.

**Решение:**
- **страница и справочный API для сайта переносятся в перспективы развития** (ТЗ, п. 4.1.6); требования НЛ перенумерованы, испытание П-27 заменено сценарием непрерывного сканирования камерой (СК-2 – СК-4);
- **поиск наличия по сети остаётся внутри приложения сотрудников** (НЛ-1 – НЛ-3): это остатки по точкам, то есть учёт, и продавец отвечает по ним покупателю в зале или по телефону;
- **признак точки «показывать на публичной странице» удаляется** из базы, контракта и формы точки: поле без страницы ничего не делает;
- **раздел 11 брендбука сохраняется** с пометкой «перспектива»: правовой разбор пригодится, если страницу сделают.

**Последствия:**
- **плюс:** на защите нет вопросов не по теме — о рекламе алкоголя в интернете (ст. 21 закона 38-ФЗ) и о границе между справкой и продвижением;
- **плюс:** время уходит на ядро темы — ревизию, сверку с ЕГАИС и отчёты;
- ключи API для внешних систем (ИН-2) остаются: ими пользуется любая внешняя система, не только сайт.

**Отвергнуто:**
- **оставить страницу в урезанном виде:** даже без цен она требует отдельного приложения, ограничения частоты запросов, своего оформления под вывеской сети и правового обоснования;
- **убрать вместе с ней кассу:** продажи нужны самому учёту — без них остаток не уменьшается, журнал продаж и сверка с ЕГАИС невозможны. Касса остаётся клиентом кассового API (КС-6) и показывает, что этого API хватит любой кассовой программе.
