# 0025. Поиск по номенклатуре и разбор сканов

**Статус:** принято, 23.10.2026.

**Контекст.** НСИ-8 требует искать по артикулу, наименованию, штрихкоду, алкокоду и скану марки. Сотрудник не выбирает, по чему ищет: в одно поле он вводит слово или сканирует код.

**Решение:**
- **одно поле, сервер сам понимает строку:**
  - марка ЕГАИС старого образца (68 символов) — алкокод в символах 8–19 по основанию 36;
  - код «Честного знака» — GTIN после (01);
  - 19 цифр — алкокод; цифры EAN/UPC — штрихкод или GTIN;
  - остальное — слова наименования и часть артикула;
- **сканер — это клавиатура:** снимаются префикс символики `]d2` и служебные FNC1/GS; буквы, набранные в русской раскладке, переводятся обратно в латиницу; Enter запускает поиск сразу;
- **полнотекстовый поиск PostgreSQL:** вычисляемая колонка `search` (наименование и разновидность, конфигурация `russian`) с индексом GIN; каждое слово ищется с начала (`тайг:*`), морфология находит «водка» по «водки»;
- **марка нового образца (150 символов) алкокода не содержит,** поэтому экран честно сообщает: товар по ней найдётся после приёмки, когда марка попадёт в систему;
- **результат — по наименованию,** страницы по ключу `(name, id)`.

**Последствия:**
- **плюс:** нет отдельного поискового сервиса, поиск меняется в одной транзакции с данными;
- **плюс:** формат марки подтверждён по двум открытым реализациям; тесты содержат настоящие примеры марок;
- без ранжирования по релевантности: для каталога в тысячи позиций порядок по названию предсказуемее.

**Отвергнуто:**
- **Elasticsearch / Meilisearch:** ещё один сервис и синхронизация данных ради каталога, который помещается в PostgreSQL;
- **`LIKE '%…%'` по наименованию:** без морфологии и без индекса.
