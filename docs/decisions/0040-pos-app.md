# 0040. Касса — отдельное веб-приложение по адресу /pos/ с очередью чеков без связи

**Статус:** принято, 24.10.2026.

**Контекст.** Учебной кассой должен пользоваться продавец-кассир на ПК со сканером или на планшете. Связь в магазине пропадает, а покупатель не должен ждать. Регистрация кассы не должна требовать ручного ввода длинного ключа.

**Решение:**
- **отдельное приложение `web/apps/pos`** на том же стеке (Vue, Vuetify, общий пакет сканера и звуков), без маршрутизатора: экраны «настройка → вход → смена → чек» переключаются по состоянию. Оно пользуется только кассовым API (`@pikni/api/pos`);
- **адрес `/pos/` на том же сервере**, что и основное приложение. QR-код в «Кассах» содержит ссылку `…/pos/#key=…`: камера планшета открывает кассу уже настроенной, ключ после `#` не попадает в журналы веб-сервера и сразу убирается из адресной строки. В разработке Vite основного приложения проксирует `/pos/` на сервер кассы;
- **QR-коды рисует тот же zxing-wasm**, что распознаёт (модуль записи), — новой зависимости нет;
- **на устройстве хранятся** ключ кассы, сессия кассира, открытая смена и каталог с ценами и МРЦ. Без связи касса находит товар по штрихкоду в каталоге;
- **без связи пробивается только товар без марок и кодов**: их проверяет ЕГАИС и «Честный знак». Такой чек сохраняется в очереди на устройстве с отметкой `offline` и временем пробития; очередь отправляется по порядку при появлении связи и раз в минуту. Отказ сервера по отложенному чеку не теряется — чек откладывается для разбора управляющим;
- **оболочка кешируется сервис-воркером**: касса открывается и после перезагрузки без связи; запросы к API не кешируются никогда;
- **горячие клавиши** (КС-7): F2 — ввод кода, F4 — количество, F8 — удалить строку, F9 — карта, F10 — наличные, Esc — отменить чек. Аппаратный сканер принимается без фокуса в поле.

**Последствия:**
- **плюс:** касса доказывает достаточность кассового API — у неё нет доступа ни к чему другому;
- **плюс:** регистрация кассы на защите — один скан QR-кода;
- **минус:** второй сервер Vite в разработке; `task dev` запускает оба;
- **камера** на экране чека — тот же компонент, что на «Сканере» (перенесён в общий пакет `@pikni/ui`); включённая камера остаётся включённой после перезагрузки;
- **отложено:** печать на чековом принтере (сейчас — печать страницы браузером).

**Отвергнуто:**
- **касса как раздел приложения сотрудников:** смешала бы два входа и две модели автономности и не показала бы, что API хватает внешней кассе;
- **готовый плагин PWA:** ради одного файла кеширования добавлял зависимость и генерацию; ручной сервис-воркер — 40 строк.
