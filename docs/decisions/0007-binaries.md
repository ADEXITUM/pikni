# 0007. Отдельные бинарники из одного модуля

**Статус:** принято, 22.10.2026.

**Контекст.** API и обработчик фоновых задач должны работать разными процессами: тяжёлая задача не должна тормозить ответы API, масштабировать их нужно независимо. При этом формат задач, которые ставит API, должен понимать обработчик той же версии.

**Решение.** Модуль `api/` содержит несколько точек входа в `cmd/`:
- `pikni-api`;
- `pikni-worker`;
- `pikni-migrate`;
- `pikni-seed`.

Все собираются в один Docker-образ и запускаются разными контейнерами.

**Последствия:**
- **плюс:** процессы изолированы, версии всегда совпадают, код общий;
- обработчик можно перенести на другой сервер: ему нужна только база;
- подкоманды разбирать не нужно, каждый `main` простой.

**Отвергнуто:**
- **один бинарник с подкомандами:** работает так же, но так понятнее, что это разные программы;
- **API и задачи в одном процессе:** падение или нагрузка задач задели бы API.
