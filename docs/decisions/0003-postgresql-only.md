# 0003. PostgreSQL — единственное хранилище

**Статус:** принято, 22.10.2026.

**Контекст.** Учёт требует транзакций. Набор характеристик товара зависит от категории. Нужны фоновые задачи с повторами и события реального времени.

**Решение.** Всё в PostgreSQL 18:
- **данные** — нормализованная схема, неизменяемые журналы защищены триггерами и ограничениями;
- **характеристики товаров** — поле JSONB по схеме категории, индекс GIN;
- **очередь задач** — River: задача ставится в той же транзакции, что и данные;
- **события между копиями сервера** — LISTEN/NOTIFY;
- **идентификаторы** — встроенная `uuidv7()`.

**Последствия:**
- одна система хранения: одни резервные копии, одно сопровождение, нет рассинхронизации хранилищ;
- задача или событие отменённой транзакции не существует;
- NOTIFY не хранит события, поэтому клиент после переподключения перезапрашивает данные, а состояние всегда в БД.

**Отвергнуто:**
- **MongoDB:** вторая база без транзакций с основной;
- **RabbitMQ и Kafka:** запись в БД и публикация не атомарны, понадобились бы паттерн outbox и ретранслятор; лишний кластер;
- **Redis для кеша:** устаревший остаток опаснее медленного.
