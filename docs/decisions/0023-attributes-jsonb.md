# 0023. Характеристики позиций — JSONB по схеме категории

**Статус:** принято, 23.10.2026.

**Контекст.** Набор характеристик зависит от категории: у вина цвет, сахар и сорт винограда, у коньяка выдержка, у пива стиль. По ним работают фильтры наличия и подбор аналогов (НЛ-7), поэтому данные должны быть чистыми.

**Решение:**
- **схема в справочнике:** `category_attributes` — код, название, тип (список, число, текст, да/нет), значения списка, признаки «в фильтрах» и «для аналогов»; подкатегория наследует характеристики предков;
- **значения — в `products.attributes` (JSONB)** с индексом GIN;
- **строгая проверка при сохранении:** сервер не примет характеристику, которой нет в схеме категории, значение не того типа или вне списка;
- **схема меняется без потери данных:** код и тип после создания не меняются; значения списка добавляются и отправляются в архив, но не удаляются; архивное значение остаётся у заведённых позиций, но новой позиции его не назначить;
- **код уникален во всей ветке категорий,** иначе позиция получила бы две характеристики с одним кодом.

**Последствия:**
- **плюс:** новая характеристика заводится через экран, без миграции;
- **плюс:** позиции, остатки и характеристики меняются в одной транзакции одной базы;
- при смене категории характеристики, которых нет в новой схеме, нужно убрать — экран делает это сам и предупреждает.

**Отвергнуто:**
- **EAV (таблица «позиция — характеристика — значение»):** соединения на каждый фильтр и слабая типизация;
- **MongoDB:** вторая СУБД ради одного поля и потеря общей транзакции (решение 0003);
- **мягкая проверка:** мусорные значения ломают фильтры и подбор аналогов.
