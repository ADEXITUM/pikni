# 0033. Импорт обновляет каталог — отличия решаются как конфликты слияния

**Статус:** принято, 24.10.2026. Дополняет решение 0027.

**Контекст.** Первая версия импорта только создавала позиции. Повторная загрузка того же файла падала на занятых штрихкодах с непонятной ошибкой, а позиции без штрихкодов задваивались. Обновить цены файлом было нельзя, хотя переоценка по прайсу — главный сценарий работы с ценами в сети.

**Решение:**
- **позиция уникальна по паре «производитель + наименование»** без учёта регистра (уникальный индекс): вручную второй «Тайги» не завести, а импорт по этой паре находит позицию, которая уже есть;
- **вариант находится по фасовке** (объём, масса, тара, упаковка); новых вариантов и штрихкодов импорт просто добавляет;
- **каждое отличие файла от каталога — отдельная строка** «в каталоге / в файле»: поля позиции, алкокод и GTIN, розничная и закупочная цены. Пользователь по каждой выбирает, что оставить, как при разрешении конфликтов слияния в git; по умолчанию — значение из файла, есть кнопки «всё из файла» и «всё оставить»;
- **ключ отличия — номер строки и поле.** Сервер между шагами ничего не хранит: на загрузку клиент отправляет тот же файл и список принятых ключей, а непринятые отличия остаются как в каталоге;
- **перед загрузкой — итог в окне подтверждения:** сколько создаётся и какие значения меняются.

**Последствия:**
- **плюс:** прайс поставщика загружается тем же импортом, и видно каждую меняющуюся цену до сохранения;
- **плюс:** дубли позиций невозможны ни через импорт, ни вручную — это гарантирует база;
- принятая цена из файла начинает действовать с момента загрузки; плановые цены с датой из файла — расширение на будущее.

**Отвергнуто:**
- **молча перезаписывать каталог файлом:** опечатка в прайсе меняет цену без следа выбора;
- **молча пропускать существующие позиции:** тогда прайсом нельзя обновить цены;
- **хранить предпросмотр на сервере с идентификатором:** таблица, сроки хранения и чистка ради одного повторного запроса (как и в решении 0027).
