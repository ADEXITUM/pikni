# 0008. Docker Compose, а не Kubernetes

**Статус:** принято, 22.10.2026.

**Контекст.** Один VPS, около десяти контейнеров, сопровождение одним человеком.

**Решение.** Docker Compose:
- **при разработке** (`deploy/compose.dev.yaml`) в контейнерах только инфраструктура: PostgreSQL и стек Grafana по профилю `obs`. API и фронтенд запускаются нативно одной командой `task dev`: на Windows так быстрее и проще отлаживать;
- **на стенде** — все сервисы в Compose;
- **масштабирование** — `--scale api=2 --scale worker=2`: копии не хранят состояние в памяти, задачи распределяются через БД, Caddy балансирует запросы.

**Последствия:**
- **плюс:** нет накладных расходов оркестратора, один файл конфигурации;
- **минус:** при падении всего сервера система недоступна до восстановления из резервной копии (до 4 ч по ТЗ);
- контейнеры без состояния переносятся в оркестратор без переделки кода — это перспектива развития.

**Отвергнуто:**
- **Kubernetes:** нужно минимум три сервера, плоскость управления занимает 1–2 ГБ памяти, отдельная область сопровождения;
- **Docker Swarm:** остаётся промежуточным вариантом для нескольких серверов;
- **приложения в Docker при разработке на Windows:** медленный доступ к файлам и отслеживание изменений, лишние образы.
