# 0020. Журнал действий: запись в транзакции изменения, коды событий, курсор

**Статус:** принято, 23.10.2026.

**Контекст.** ПБ-7 требует фиксировать входы, изменения документов, справочников и прав, а журнал — фильтровать и выгружать. Запись должна быть осмысленной («сброшен пароль петровой»), а не технической («POST /users/…/password 200»), и не должна теряться или появляться без самого изменения.

**Решение:**
- **сервис вызывает `audit.Record(ctx, tx, событие)`** в той же транзакции, что и изменение: оба сохраняются вместе или не сохраняются вовсе;
- **кто действует** — пользователь, сессия и IP — кладёт в контекст middleware после проверки сессии; у действий консоли сервера и фоновых задач пользователя нет. Тип `Actor` объявлен в `audit`, чтобы модуль журнала ни от кого не зависел;
- **в базе хранится код события** (`auth.login_failed`, `user.updated`); перечень — `AuditAction` в контракте; русские названия — словарь клиента для экрана и словарь сервера для выгрузки, полноту обоих проверяют тесты;
- **подробности** — JSONB (`reason`, `changes` с парами «было/стало»); клиент показывает их по-человечески, незнакомые поля — как есть;
- **при входе с несуществующим логином** введённый текст не сохраняется: в это поле по ошибке вводят пароль;
- **постраничный вывод по курсору** (`before` = номер последней записи): журнал только растёт, номер возрастает, любая страница выбирается по индексу одинаково быстро;
- **выгрузка XLSX** (excelize, построчная запись) с теми же фильтрами и временем в часовом поясе пользователя; больше 50 000 строк за раз не выгружается.

**Последствия:**
- **плюс:** журнал всегда согласован с данными; откат изменения откатывает и запись (это проверяет тест);
- **плюс:** коды удобно фильтровать, формулировки можно менять без миграции данных;
- минус: при «Показать ещё» нельзя перейти сразу на N-ю страницу;
- минус: русские названия есть в двух местах — клиент и выгрузка.

**Отвергнуто:**
- **автоматическая запись каждого HTTP-запроса в middleware:** нет смысла события, не видны действия консоли и фоновых задач;
- **триггеры БД на каждую таблицу:** запись на уровне строк, а не действий, и базе нужно отдельно передавать, кто действует;
- **постраничный вывод по номеру страницы (`OFFSET`):** медленнее на дальних страницах, а новые записи сдвигают страницы при листании.
