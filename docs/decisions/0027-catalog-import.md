# 0027. Импорт номенклатуры — пробный прогон в транзакции

**Статус:** принято, 23.10.2026.

**Контекст.** НСИ-7: импорт из XLSX/CSV по шаблону, перед загрузкой — предпросмотр и ошибки по строкам; если есть ошибки, ничего не загружается. Проверки при импорте должны совпадать с ручным вводом: МРЦ, характеристики, связи бренда и производителя.

**Решение:**
- **предпросмотр — это настоящий импорт, который в конце откатывается:** все строки проходят через те же методы сервиса, что и экран, внутри одной транзакции;
- **каждая позиция — в своей точке сохранения:** ошибка откатывает только её, проверка идёт дальше, и пользователь видит ошибки всех строк сразу;
- **загрузка** — тот же прогон, транзакция фиксируется, только если ошибок нет;
- **сервер ничего не хранит между шагами:** для загрузки клиент отправляет тот же файл ещё раз;
- **одна строка — позиция с одним вариантом;** строки с одинаковыми наименованием и производителем — одна позиция с несколькими вариантами;
- **недостающие производители, бренды и линейки создаются,** предпросмотр перечисляет их, чтобы опечатка была видна до загрузки;
- **демо-каталог стенда — CSV, загружаемый тем же импортом** (`pikni-admin import-catalog`), а тест проверяет, что он проходит все правила.

**Последствия:**
- **плюс:** одна реализация правил вместо двух, предпросмотр не может разойтись с загрузкой;
- **плюс:** «всё или ничего» гарантирует транзакция базы, а не код;
- предпросмотр расходует номера артикулов из последовательности; до 5000 строк импорт идёт прямо в запросе, фоновая задача понадобится позже.

**Отвергнуто:**
- **отдельный валидатор файла:** второй набор правил, который отстанет от первого;
- **хранение загрузки на сервере между шагами:** таблица, сроки хранения и чистка ради одного повторного запроса.
