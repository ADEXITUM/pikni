# 0009. Vue 3 и Vuetify; отказ от PrimeVue

**Статус:** принято, 22.10.2026.

**Контекст.** Нужны три клиентских приложения (сотрудники, касса, справочная страница) с общими частями, богатые таблицы, работа на телефоне. Внутренней системе SSR и поисковая оптимизация не нужны.

**Решение:**
- **Vue 3, TypeScript, Vite** — SPA и PWA. В курсовой был Nuxt, здесь SSR не нужен. После сборки — статические файлы, их отдаёт Caddy;
- **Vuetify 4** (MIT) с темой из брендбука и умолчаниями без теней и ряби;
- **TanStack Query** — для данных с сервера, **Pinia** — для состояния приложения;
- **рабочее пространство npm:** `apps/staff`, `apps/pos`, `apps/public` и общие пакеты `packages/api` и `packages/ui`;
- **стиль кода** — Prettier без точек с запятой; проверки — vue-tsc, oxlint, ESLint.

**Последствия:**
- **плюс:** пакеты отдают исходники TypeScript, отдельной сборки у них нет;
- **плюс:** касса и справочная страница подключат ту же тему и клиент API.

**Отвергнуто:**
- **PrimeVue:** с версии 5 — коммерческая лицензия. Нужен лицензионный ключ, бесплатный тариф продлевается ежегодно и не подходит компании больше чем на 10 сотрудников. Учебному заказчику на 33 сотрудника пришлось бы покупать лицензию, а это противоречит ТЗ (п. 4.4.11). Версия 4 под MIT получает только исправления безопасности;
- **микрофронтенды:** решают задачу нескольких команд, у нас один разработчик.
