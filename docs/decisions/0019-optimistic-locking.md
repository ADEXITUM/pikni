# 0019. Оптимистическая блокировка при редактировании

**Статус:** принято, 23.10.2026.

**Контекст.** Два администратора могут одновременно открыть карточку сотрудника и сохранить разные изменения. Без защиты второй молча затрёт правки первого. Позже то же касается документов, справочников и цен.

**Решение:**
- **у редактируемой записи есть `version`**; любое изменение, включая блокировку, увеличивает её;
- **форма отправляет версию**, с которой карточка была открыта;
- **в транзакции** запись блокируется `SELECT … FOR UPDATE`, версия сравнивается с присланной; при расхождении — ответ 409 «Данные изменил другой администратор — обновите и повторите», форма не закрывается;
- **изменение записывается в журнал** с разницей «было → стало» только по изменившимся полям.

**Последствия:**
- **плюс:** чужие правки не теряются, а пользователь понимает, что произошло;
- **плюс:** блокировка держится миллисекунды, только на время транзакции, а не пока открыта форма;
- при частых одновременных правках одной записи пользователям чаще придётся повторять — для справочников это редкость.

**Отвергнуто:**
- **последний сохранивший прав:** тихая потеря данных;
- **пессимистическая блокировка на время редактирования** («карточку редактирует Иванов»): забытые открытые формы блокируют запись, нужны тайм-ауты и снятие блокировок.
