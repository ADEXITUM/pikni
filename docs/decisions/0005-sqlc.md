# 0005. sqlc вместо ORM

**Статус:** принято, 22.10.2026.

**Контекст.** Учётные запросы — оборотная ведомость, остатки на дату, сверка с ЕГАИС — сложные, и их нужно уметь показать и объяснить. Ошибки в SQL хочется ловить до запуска.

**Решение.** SQL пишется руками в `api/db/queries/<модуль>/*.sql`. sqlc читает схему из миграций, проверяет запросы и генерирует типизированный Go-код в пакет `store` своего модуля. sqlc запускается в Docker-образе с закреплённой версией, потому что под Windows без компилятора C он не собирается.

**Последствия:**
- **плюс:** SQL виден целиком, опечатка в колонке ловится при генерации, нет рефлексии во время работы;
- **плюс:** сгенерированный код работает и с пулом, и с транзакцией (`DBTX`);
- **минус:** запросы с большим числом необязательных фильтров на sqlc неудобны. Для поиска наличия возможна динамическая сборка SQL, решим в итерации 7.

**Отвергнуто:**
- **GORM и другие ORM:** скрывают SQL, ошибки проявляются во время работы;
- **один общий пакет запросов на все модули:** модуль мог бы обратиться к чужой таблице в обход её сервиса.
