# 0017. Интеграционные тесты на testcontainers с базой-шаблоном

**Статус:** принято, 23.10.2026.

**Контекст.** Самое важное поведение живёт в базе: ограничения, триггеры, права ролей, транзакции, блокировки строк. Подмена базы в тестах (mock) проверяет только то, что код вызывает нужный метод, но не то, что база действительно отклонит запись.

**Решение:**
- **пакет `dbtest`** поднимает настоящий PostgreSQL 18 в Docker через testcontainers-go — тем же образом и тем же скриптом ролей, что в разработке;
- **контейнер один на пакет тестов;** миграции применяются один раз к базе-шаблону;
- **каждый тест получает свою копию:** `CREATE DATABASE test_N TEMPLATE pikni` занимает десятки миллисекунд, тесты не мешают друг другу и идут параллельно;
- **тест получает два пула** — владельца и приложения, чтобы проверять поведение под каждой ролью;
- **контейнер удаляет Ryuk** после завершения процесса тестов; `go test -short` интеграционные тесты пропускает;
- **HTTP-тесты** собирают сервер так же, как `main`, и ходят в него через `httptest` с cookie и CSRF, как браузер.

**Последствия:**
- **плюс:** тесты проверяют настоящую работу: блокировку входа, откат журнала вместе с изменением, конфликт версий, права ролей БД;
- **плюс:** время прогона — секунды: первый запуск пакета около 3 с, дальше по десяткам миллисекунд на тест;
- для тестов нужен Docker; в CI на GitHub Actions он есть.

**Отвергнуто:**
- **mock базы:** не ловит ошибки SQL, ограничений и транзакций;
- **общая база для всех тестов с очисткой таблиц:** тесты зависят друг от друга и не идут параллельно;
- **контейнер на каждый тест:** секунды на тест вместо миллисекунд.
