# 0058. Стенд: два экземпляра API за Caddy, копии pg_dump, метрики в Grafana

**Статус:** принято, 24.10.2026. Сервер и домен не арендованы — конфигурация проверена локально.

**Контекст.** Раздел 7 ТЗ: отказ экземпляра (П-36), восстановление из копии не дольше 4 часов (П-34),
наблюдаемость и оповещения (п. 4.1.5), выкладка.

**Решение:**
- **образы:** серверный (API, миграции, утилита, имитатор — решение 0007) на distroless и веб — Caddy
  с собранными staff и кассой. Проверку живучести выполняет сам бинарник (`-healthcheck`): в образе
  без оболочки нет curl;
- **Caddy** выдаёт сертификат Let's Encrypt для `PIKNI_DOMAIN` сам; без домена — самоподписанный на
  localhost. API — два экземпляра с проверкой готовности: упавший исключается, запрос повторяется на
  втором. Фоновые задачи выполняет ведущий экземпляр River (решение 0055);
- **копии:** `backup.sh` по cron — `pg_dump -Fc`, запись в журнал `backups`, хранение 14 дней;
  `restore.sh` — пересоздание базы, миграции, запуск. Страница «Состояние системы» и уведомление
  «нет копии за сутки» читают журнал;
- **наблюдаемость:** OpenTelemetry — HTTP, SQL и запросы к имитатору в одной трассировке. Фоновая
  задача River и каждое отправленное или полученное сообщение ЕГАИС начинают свою трассировку, а пустые
  опросы УТМ (раз в несколько секунд) не записываются; бизнес-метрики
  (чеки и сканы, очередь ЕГАИС, недоступные УТМ, недостачи, очередь задач); дашборд и правила
  оповещений Grafana — файлы в репозитории;
- **выкладка** — ручной workflow: образы в GHCR, `compose pull && up -d` по SSH после копии. Без
  секретов стенда задание пропускается.

**Проверено локально:** сборка обоих образов; запуск всего стека; HTTPS через Caddy; при остановленном
экземпляре 20 из 20 запросов успешны; смена ведущего River за 19 с без дублей задач; копия 0,3 МБ и
восстановление за 2 с; 100 виртуальных пользователей — p95 4 мс. П-37 (25.10): трассировка
`POST /api/pos/v1/checks` содержит SQL и запрос к «Честному знаку» имитатора, приём ТТН — транзакцию
и подтверждение в УТМ; все панели дашборда с данными; правило «УТМ недоступен» срабатывает на
сообщении, которое ждёт дольше 5 минут. Запросы правил — мгновенные (`instant`): с рядом значений
Grafana не вычисляла условие.

**Отвергнуто:**
- **Kubernetes:** для одного сервера и диплома избыточен (решение 0008);
- **непрерывная репликация (WAL-G, PITR):** точнее суточной копии, но сложнее в сопровождении; пункт
  на развитие вместе с отправкой копий в объектное хранилище.
